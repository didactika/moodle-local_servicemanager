# GitLab CI/CD Configuration

## Overview

This GitLab CI/CD pipeline automatically:
- ✅ Creates version tags based on `version.php`
- ✅ Updates SonarQube project version automatically
- ✅ Runs SonarQube quality checks on merge requests
- ✅ Generates vulnerability reports

## Structure

```
.ci/
├── README.md                          # This file
└── tag-control/                       # Automation scripts
    ├── validate_version.sh            # Validates and extracts version info
    ├── update_sonar_version.sh        # Updates sonar-project.properties
    ├── setup_git.sh                   # Configures git for CI environment
    ├── create_tag.sh                  # Creates and pushes git tag
    └── verify_tag.sh                  # Verifies tag creation

.gitlab-ci.yml                         # Pipeline configuration (calls scripts)
sonar-project.properties               # SonarQube configuration (auto-updated)
```

## Pipeline Stages

```
┌─────────────────────────┐
│  1. validate            │  All branches
│  - validate_version     │  Extract version from version.php
│  - update_sonar_version │  Update sonar-project.properties (MRs only)
└────────┬────────────────┘
         │
         ▼
┌─────────────────────────┐
│  2. sonarqube-check     │  Merge Requests only
│  - Code quality scan    │  Runs SonarQube analysis
└────────┬────────────────┘
         │
         ▼
┌─────────────────────────┐
│  3. sonarqube-vuln      │  Merge Requests only
│  - Vulnerability report │  Exports SAST report
└────────┬────────────────┘
         │
         ▼
┌─────────────────────────┐
│  4. tag                 │  All branches
│  - create_version_tag   │  Creates tag (auto/manual)
│  - verify_tag           │  Verifies tag creation
└─────────────────────────┘
```

## Scripts

### 1. `validate_version.sh`

Validates `version.php` and extracts version information.

**Usage:**
```bash
./validate_version.sh [version_file]
```

**Output:**
- `version.env` - Dotenv file with RELEASE, MATURITY, TAG_NAME
- `release.txt` - Release version
- `maturity.txt` - Maturity level
- `tag_name.txt` - Generated tag name

### 2. `update_sonar_version.sh` ✨ NEW

Updates `sonar-project.properties` with version from `version.php`.

**Usage:**
```bash
./update_sonar_version.sh [version_file] [sonar_file]
```

**What it does:**
- Extracts `$plugin->version` from version.php
- Updates `sonar.projectVersion` in sonar-project.properties
- Ensures SonarQube tracks the correct version

### 3. `setup_git.sh`

Configures git user and authentication for CI environment.

### 4. `create_tag.sh`

Creates an annotated git tag and pushes it to the remote repository.

### 5. `verify_tag.sh`

Verifies that the tag was created successfully.


## Tag Naming Convention

| Maturity Constant | Tag Suffix | Example |
|-------------------|------------|---------|
| `MATURITY_ALPHA` | `-alpha` | `v2.1.0-alpha` |
| `MATURITY_BETA` | `-beta` | `v2.1.0-beta` |
| `MATURITY_RC` | `-rc` | `v2.1.0-rc` |
| `MATURITY_STABLE` | _(none)_ | `v2.1.0` |

## Usage

### Automatic Tagging

1. Update `version.php`:
   ```php
   $plugin->release = '2.2.0';
   $plugin->maturity = MATURITY_BETA;
   ```

2. Commit and push to main branch:
   ```bash
   git add version.php
   git commit -m "Bump version to 2.2.0-beta"
   git push origin main
   ```

3. Pipeline automatically creates tag `v2.2.0-beta`

### Manual Tagging

You can manually trigger the tag creation job on any branch:

1. Go to: `CI/CD > Pipelines`
2. Find your pipeline
3. Click on `create_version_tag` job
4. Click "Play" button

## Environment Variables

The pipeline uses these GitLab CI variables:

- `CI_COMMIT_BRANCH`: Current branch name
- `CI_DEFAULT_BRANCH`: Default branch (main/master)
- `CI_COMMIT_SHA`: Full commit SHA
- `CI_COMMIT_SHORT_SHA`: Short commit SHA
- `CI_JOB_TOKEN`: Authentication token for git operations
- `CI_PROJECT_PATH`: Project path (group/project)
- `CI_SERVER_HOST`: GitLab server hostname

## Rules

### validate_version job
- ✅ Runs on all branches
- ✅ Runs on all commits

### create_version_tag job
- ✅ Runs automatically on `main`/`master` branch
- ✅ Runs automatically on `release/*` branches
- ✅ Available as manual job on other branches
- ❌ Skips if running on an existing tag

### verify_tag job
- ✅ Runs on `main`/`master` branch after tag creation
- ⚠️ Allowed to fail (informational only)

## Files

- `.gitlab-ci.yml`: Main CI/CD configuration
- `.ci/extract_version.sh`: Helper script to extract version info (optional)

## Troubleshooting

### Tag already exists

If the tag already exists, the pipeline will skip creation:
```
ℹ️  Tag 'v2.1.0-alpha' already exists. Skipping creation.
```

**Solution**: Update the version in `version.php` to a new version.

### Permission denied

If you get permission errors:
```
❌ Permission denied (publickey)
```

**Solution**: Ensure the GitLab project has proper permissions for CI/CD:
- Settings > CI/CD > Variables
- Check that protected branches allow CI to push tags

### Invalid maturity

If maturity constant is not recognized:
```
❌ Error: Unknown maturity code: MATURITY_UNKNOWN
```

**Solution**: Use only valid maturity constants:
- `MATURITY_ALPHA`
- `MATURITY_BETA`
- `MATURITY_RC`
- `MATURITY_STABLE`

## Best Practices

1. **Bump version before merging**: Update `version.php` in your feature branch
2. **Use semantic versioning**: Follow MAJOR.MINOR.PATCH format
3. **Progress through maturities**: alpha → beta → rc → stable
4. **Don't reuse versions**: Each version should have a unique tag

## Example Workflow

```bash
# Feature branch
git checkout -b feature/new-reports
# ... make changes ...

# Before merging, bump version
# Edit version.php:
$plugin->release = '2.2.0';
$plugin->maturity = MATURITY_ALPHA;

git add version.php
git commit -m "Bump version to 2.2.0-alpha"
git push origin feature/new-reports

# Create merge request and merge to main
# Pipeline automatically creates v2.2.0-alpha tag

# Later, when ready for beta
git checkout main
git pull
# Edit version.php:
$plugin->maturity = MATURITY_BETA;

git add version.php
git commit -m "Bump to 2.2.0-beta"
git push origin main

# Pipeline automatically creates v2.2.0-beta tag
```

## Security

- Uses `CI_JOB_TOKEN` for authentication (automatically provided by GitLab)
- No credentials stored in repository
- Tags are immutable once created
- Only runs on protected branches by default
